# مدیریت پروکسی چند پورتی (General Proxy Manager)

[English](/README-EN.md) | [简体中文](/README.md) | فارسی

یک درگاه و مولد پیکربندی چند پورتی و تفکیک‌شده محلی بر پایه هسته **sing-box 1.13.18**.

ابزاری سبک، کاملاً سمت کاربر (Client-Side) و با رعایت کامل حریم خصوصی که به شما امکان می‌دهد $N$ نود پروکسی مجزا را وارد کرده و دقیقاً $N$ اندپوینت (پورت) محلی مستقل و ایزوله تولید کنید. در این معماری، هر پورت محلی منحصراً به یک نود خروجی و مسیر اختصاصی DNS متصل می‌شود.

---

## 🎯 هدف اصلی و کاربردها

در سناریوهایی نظیر مدیریت حساب‌های کاربری متعدد، فراخوانی APIهای هوش مصنوعی با اکانت‌های مختلف (مانند **NVIDIA NIM API** یا نمونه‌های متعدد **OpenCode**)، توسعه خزنده‌های وب (Web Scraping)، تست‌های یکپارچه‌سازی و خودکارسازی، برنامه‌ها نیازمند استفاده همزمان از IPهای خروجی متفاوتی هستند.

کلاینت‌های پروکسی سنتی معمولاً فقط یک پورت شنود سراسری ارائه می‌دهند. **General Proxy Manager** یک معماری قطعی، تفکیک‌شده و ۱ به ۱ ایجاد می‌کند:

```
LOCAL PROXY PORT (پورت محلی)
        ↓
SING-BOX INBOUND (Mixed: همزمان SOCKS5 و HTTP)
        ↓
EXACTLY ONE OUTBOUND (دقیقاً یک خروجی اختصاصی)
        ↓
REMOTE PROXY (سرور پروکسی مقصد)
        ↓
INTERNET
```

### نمونه نقشه‌برداری پورت‌ها:
- `127.0.0.1:10808` → `proxy-in-01` → `proxy-out-01` (پروکسی ۱)
- `127.0.0.1:10809` → `proxy-in-02` → `proxy-out-02` (پروکسی ۲)
- `127.0.0.1:10810` → `proxy-in-03` → `proxy-out-03` (پروکسی ۳)
- ...
- `127.0.0.1:(10808 + N - 1)` → `proxy-in-N` → `proxy-out-N` (پروکسی N)

هر پورت به عنوان یک درگاه مستقل عمل می‌کند. هیچ تداخل مسیریابی بین پورت‌ها وجود ندارد و در صورت قطع ارتباط پروکسی، ترافیک به هیچ‌وجه به صورت مخفیانه به اتصال مستقیم (Direct) نشت نخواهد کرد (`route.final = "block"`).

## ✨ قابلیت‌های کلیدی

- **تفکیک قطعی و ۱ به ۱ پورت‌ها و خروجی‌ها**: هر نود فعال یک پورت محلی اختصاصی دریافت کرده و قوانین مسیریابی به طور دقیق هر ورودی را به خروجی متناظرش متصل می‌کنند.
- **تطابق کامل با نسخه ۱.۱۳.۱۸ سینگ‌باکس**: بر اساس قواعد و اسکیماهای رسمی **sing-box 1.13.18** توسعه یافته و با باینری رسمی تست شده است (`SUPPORTED_SING_BOX_VERSION = "1.13.18"`).
- **پشتیبانی دوگانه (Mixed Inbound)**: هر پورت محلی همزمان از پروتکل‌های **SOCKS5** و **HTTP Proxy** پشتیبانی می‌کند.
- **معماری پیشرفته و امن DNS**:
  - **دی‌ان‌اس راه‌انداز (`local_dns`)**: دامنه‌های سرورهای پروکسی را به طور مستقیم و مجزا حل می‌کند تا از بروز بن‌بست و لوپ در اتصال جلوگیری شود.
  - **دی‌ان‌اس اختصاصی تونل (`dns-proxy-XX`)**: درخواست‌های دی‌ان‌اس هر پورت از داخل تونل خروجی همان پروکسی (`detour`) عبور داده می‌شوند.
  - **اولویت با IPv4 (`prefer_ipv4`)**: برای جلوگیری از خطاهای ناشی از قطعی یا عدم پایداری IPv6 در شبکه‌ها.
- **حفظ کامل پارامترهای پیشرفته نودها**: کلون عمیق (Deep Clone) بدون دستکاری پارامترهای حساس VLESS از جمله Reality (Public Key، Short ID)، uTLS، WebSocket، gRPC، Multiplex و هدرها.
- **حفظ حداکثری حریم خصوصی (بدون واسطه شخص ثالث)**:
  - پردازش ۱۰۰٪ محلی در مرورگر، بدون ثبت لاگ و تله‌متری.
  - دریافت لینک اشتراک به صورت مستقیم توسط مرورگر (بدون ارسال لینک و مشخصات شما به پروکسی‌های عمومی شخص ثالث نظیر allorigins).
- **اعتبارسنجی ساختاری کانفیگ**: بررسی خودکار یکتایی پورت‌ها، محدوده پورت‌ها (۱ تا ۶۵۵۳۵) و عدم نشت مسیر پیش از دانلود `config.json`.

## 🔒 نکات مهم درباره دی‌ان‌اس و پروتکل‌ها (پروکسی مد در برابر تون مد)

این ابزار برای حالت **پروکسی (Proxy Mode)** طراحی شده است و حالت کارت شبکه مجازی (TUN) نیست.

سینگ‌باکس تنها ترافیکی را مدیریت می‌کند که به پورت‌های لیسن محلی آن ارسال شود. برای اطمینان از حل دی‌ان‌اس از سمت سرور پروکسی:
- **در پروتکل SOCKS5 (پیشنهاد: `socks5h://`)**: استفاده از پیشوند `socks5h://` باعث می‌شود کلاینت نام دامنه را به پروکسی بسپارد تا از راه دور حل شود.
- **در پروتکل HTTP Proxy**: درخواست‌های CONNECT به طور طبیعی نام دامنه را به پروکسی می‌سپارند.

> [!WARNING]
> چنانچه برنامه‌ای ابتدا نام دامنه را توسط دی‌ان‌اس سیستم‌عامل حل کرده و سپس به آی‌پی متصل شود، دی‌ان‌اس از سیستم محلی شما عبور خواهد کرد. برای هدایت کامل ترافیک در سطح سیستم‌عامل، از حالت TUN استفاده نمایید.

## 💻 نمونه کدهای استفاده در پروژه‌ها

### ۱. دستور cURL

با استفاده از SOCKS5h (حل دی‌ان‌اس در سرور پروکسی):
```bash
# ارسال درخواست از طریق پروکسی شماره ۱
curl --proxy socks5h://127.0.0.1:10808 https://api.ipify.org

# ارسال درخواست از طریق پروکسی شماره ۲
curl --proxy socks5h://127.0.0.1:10809 https://api.ipify.org
```

با استفاده از HTTP Proxy:
```bash
curl --proxy http://127.0.0.1:10808 https://api.ipify.org
```

---

### ۲. زبان Python (Requests / HTTPX / NVIDIA NIM API)

```python
import requests

# کلاینت اول از پورت 10808 (پروکسی ۱) استفاده می‌کند
proxies_node1 = {
    "http": "http://127.0.0.1:10808",
    "https": "http://127.0.0.1:10808"
}
resp1 = requests.get("https://api.ipify.org?format=json", proxies=proxies_node1)
print("IP پروکسی ۱:", resp1.json()["ip"])

# کلاینت دوم از پورت 10809 (پروکسی ۲) استفاده می‌کند
proxies_node2 = {
    "http": "http://127.0.0.1:10809",
    "https": "http://127.0.0.1:10809"
}
resp2 = requests.get("https://api.ipify.org?format=json", proxies=proxies_node2)
print("IP پروکسی ۲:", resp2.json()["ip"])
```

استفاده از SOCKS5h در پایتون:
```python
proxies = {
    "http": "socks5h://127.0.0.1:10808",
    "https": "socks5h://127.0.0.1:10808"
}
```

---

### ۳. زبان Node.js

```javascript
import fetch from 'node-fetch';
import { HttpsProxyAgent } from 'https-proxy-agent';

const agent = new HttpsProxyAgent('http://127.0.0.1:10808');
const res = await fetch('https://api.ipify.org?format=json', { agent });
const data = await res.json();
console.log('IP از طریق پروکسی ۱:', data.ip);
```

## 🚀 راهنمای اجرای محلی

به دلیل سیاست‌های امنیتی مرورگرها در بارگذاری ماژول‌های ES و درخواست‌های محلی، فایل را از طریق یک وب‌سرور ساده اجرا کنید:

### با استفاده از Python:
```bash
# پایتون ۳
python -m http.server 8000
```

### با استفاده از Node.js:
```bash
npx serve .
```

سپس در مرورگر خود آدرس `http://localhost:8000` را باز کنید.

- حذف نودهای غیرفعال از پورت‌های لیسن و روت‌ها
